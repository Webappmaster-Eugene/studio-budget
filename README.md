# Учёт выплат

Веб-приложение для ведения договоров и сверки расчётов. Создайте договор,
внесите работы и платежи, откройте отчёт на нужную дату. Данные сохраняются
в PostgreSQL.

## Быстрый запуск

Нужны Docker с Compose и Node.js 22.13+ для генерации настроек. Из корня репозитория:

```sh
node scripts/local-env.mjs
docker compose up -d --build
```

Откройте [127.0.0.1:3212](http://127.0.0.1:3212) и используйте логин и пароль,
которые напечатал генератор. Для другого порта запустите генератор с `APP_PORT`.
Генератор создаёт `.env` один раз. При повторном запуске он сохраняет существующий файл.
Чтобы остановить сервис, используйте `docker compose down`. Том PostgreSQL сохранится.

## Сценарий бухгалтера

1. Создайте договор, укажите номер, дату подписания и сумму.
2. На вкладке «Работы» добавьте работы. Дата постановки определяет, с какого дня
   работа видна в отчёте. Укажите дату приёмки или отмены, когда это произойдёт.
3. На вкладке «Платежи» внесите сумму и дату записи. Пустая дата оплаты оставляет
   платёж в очереди. В поле связи можно выбрать конкретную работу или договор.
   При возврате укажите его дату и сумму.
4. Перейдите на вкладку «Отчёт» и выберите дату. Сравните фактические выплаты,
   остаток к оплате по принятым работам и аванс без распределения.

Редактирование и удаление доступны из списка. При удалении договора
его работы и платежи удаляются вместе с ним. Работу с привязанным
платежом можно удалить после изменения или удаления связи с платежом.

## Импорт CSV

В рабочей области выберите «Импорт CSV» и загрузите три файла UTF-8 с запятой
и строкой заголовков. Возможен договор без работ или платежей, тогда
соответствующий файл содержит только заголовок.

| Файл | Колонки |
| --- | --- |
| `contracts.csv` | `contract_id,contractor,amount,signed_at` |
| `works.csv` | `work_id,contract_id,title,price,status,completed_at,cancelled_at` |
| `payments.csv` | `payment_id,contract_id,work_id,purpose,amount,status,created_at,paid_at,refunded_at` |

Допустимые статусы работ — `planned`, `done`, `cancelled`. Допустимые статусы
платежей — `queued`, `paid`, `refunded`. Даты в формате ГГГГ-ММ-ДД, суммы в
рублях с точкой. Импорт проверяет все ссылки и сохраняет выгрузку целиком
в одной транзакции. Повторный номер договора отклоняется. Лимит на файл
составляет 160 КБ и 2000 записей. Для работы без даты постановки импорт
берёт дату подписания договора. Возврат из CSV подразумевает полную сумму,
поскольку отдельной суммы возврата в этом формате нет.

## Расчёт

Деньги хранятся как целые копейки. Даты включаются целиком. Платёж начинает
влиять на отчёт с даты оплаты, с даты возврата сумма уменьшается на возвращённую
часть. Прямые платежи сохраняют связь с работой. Остаток без привязки
покрывает принятые работы в порядке приёмки, при совпадении даты — по ID.
Остаток показывается как аванс без распределения.

У отменённой работы остаток к оплате равен нулю. Прямые выплаты и переплаты
видны в отчёте. Сумма договора и стоимость работ выводятся отдельно.
Отчёт пересчитывает события по текущей версии записей. Сервис поддерживает
один суммарный возврат на платёж и общую рабочую область одного аккаунта.

## Устройство и проверки

Правила расчёта и их последствия описаны в [DECISIONS.md](DECISIONS.md).
Короткая инструкция для сверки находится в [ACCOUNTANT.md](ACCOUNTANT.md).

- Next.js и React отвечают за интерфейс и HTTP API. Публичен только экран входа
  и проверка работоспособности. Сервер проверяет сессию для операций с данными.
- `db/migrations/` задаёт схему PostgreSQL. Миграции выполняются транзакционно
  при старте контейнера. Записи принадлежат договору, контроль версии предотвращает
  перезапись изменений из параллельной вкладки.
- `src/lib/statement.ts` рассчитывает отчёт отдельно от базы и интерфейса.

```sh
pnpm install --frozen-lockfile
pnpm smoke
pnpm audit
```

Playwright проверяет браузер и HTTP API на уже работающем изолированном
экземпляре. Передайте `LEDGER_TEST_URL`, `LEDGER_TEST_USERNAME` и
`LEDGER_TEST_PASSWORD` от тестовой базы. Для локального браузера установите
Chromium через `pnpm exec playwright install chromium`, затем выполните
`pnpm test:e2e`. Проверки создают и удаляют собственные договоры.

## Докплой

Используйте `compose.production.yaml`, сервис `app`, порт `3000`.
Укажите `APP_ORIGIN` с точным публичным HTTPS-адресом, а также
`APP_USERNAME`, `APP_PASSWORD_HASH` и случайный
`POSTGRES_PASSWORD` из URL-безопасных символов.
Хеш пароля создаёт `node scripts/hash-password.mjs`, пароль подаётся
через стандартный ввод. Изменение хеша отзывает прежние сессии.
PostgreSQL доступен внутри сети Compose. Перед обновлением сохраните
резервную копию базы через `pg_dump` и проверьте возможность восстановления.

`GET /api/health` сообщает версию и доступность базы. Для работы вне Docker
укажите `DATABASE_URL` и настройки аккаунта, выполните `pnpm db:migrate`
и запустите `pnpm dev` либо `pnpm build` и `pnpm start`.
